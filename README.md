# DaerD (DD, ディーディー)

Unity の AnimatorController エディタを GraphView で置き換えるエディタ拡張です。
グラフでの編集に加えて、**壊さないリファクタリング**（型変換・カスケードリネーム）、
**コントローラーの解析**（静的・動的）、**仕掛けの自動生成**（オブジェクトガジェット・
DBT ガジェット・パラメーター圧縮）、**ギミックプレハブとの連携**、**C# との相互変換**を
1 つのウィンドウにまとめています。

- Unity 2022.3 以降 / パッケージ名 `net.yozolab.daerd`
- VRChat SDK・NDMF・Modular Avatar は**任意**。無くてもコンパイル・動作し、該当機能だけが隠れます

| ----------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **VCC / ALCOM**   | [これを押して追加](https://vpm.yozolab.net/)                                                                                                            |

| **手動**          | [Releases](https://github.com/YozoraKurage/DaerD/releases) から `.unitypackage` または `.zip`                                                           |

有効にすると（既定はオフ）、Project ウィンドウでのダブルクリックも DaerD に来ます。

## エディタ

### グラフ編集

- ステートマシン / サブステートマシン / ブレンドツリーをグラフで編集。複数のコントローラーをタブで同時に開けます
- **Shift + スクロール**で表示中のレイヤーを上下に切り替え
- ブレンドツリーは **Hierarchy パネル**からも辿れます（行のクリックで選択＋フレーム、
  ダブルクリックで入れ子ツリーへ潜る、開閉はシーンの Hierarchy と同じ操作）
- **ホーム画面** — レイヤー一覧で Home を選ぶとグラフの代わりに出る、コントローラー全体の画面。
  プレハブリンク（パラメーターストアのスロット込み）、生成した仕掛けの記録と入口
  （DBT ガジェット・オブジェクトガジェット・巡回同期・C# Recipe）、
  全体に効くツールが集まります。ガジェットや同期設定は展開するとツリーの壁になって
  読み返せないので、**コントローラーと一緒に保存されたこの記録が唯一の説明**になります
- **DD データの分離と破棄**（ホーム画面の Controller カード） — DaerD の保存データは
  既定でコントローラーのサブアセットですが、**分離**すると `Assets/zz_DaerD/…` の
  専用ファイルへ移り、コントローラー側から DaerD の痕跡が消えます（配布用。手元では
  そのまま使え、**統合**で戻せます）。**破棄**は保存データを丸ごと消します。
  どちらもコントローラー本体（レイヤー・パラメーター・モーション）は無傷です

### 遷移の優先順位

Animator は 1 つのステートから出る遷移を**リスト順に評価**し、条件を満たした最初の 1 本が勝ちます。
ステートを選ぶとその全遷移が評価順に並び、ドラッグで並べ替えられます（Entry / Any State も同じ一覧）。
行にマウスを乗せるとグラフ側の該当エッジが色付き、Solo された遷移に阻まれて評価されない遷移は
Mute と同じ赤で表示されます。

### 検索とジャンプ

ツールバーの検索欄からステート名・モーション名で**全レイヤーを横断検索**してジャンプ。
候補は ↑↓ で選べます。

### Animation ウィンドウ連携

- **Select Sync** — 選択中ステートのクリップを Unity の Animation ウィンドウへ送り、タイムラインを即座に切り替え
- **Preview** — 選択が変わるたびに Animation ウィンドウのプレビューを取り直し、シーンのポーズを追従させる
  （Select Sync が前提なので、Preview を入れると自動で有効になります）

どちらも Animation ウィンドウの状態に副作用があるため、ツールバーからの**オプトイン**です。

## 壊さないリファクタリング

### パラメーターの型変換

パラメーターの型を変えると、それを参照している**条件を全部書き換え**てコントローラーを
有効なまま保ちます（モード / しきい値の対応付けは純粋関数として単体テスト済み）。適用前に差分プレビュー。

### カスケードリネーム

リネームすると、条件・ブレンドツリー（Direct の子ウェイトや Synced レイヤーの上書きツリーを含む）・
ステートのフィールド・VRC Parameter Driver のエントリまで**新しい名前が波及**します。Unity 標準はここをやりません。
参照の別パラメーターへの付け替え（リマップ）、参照ごと消す**クリーン削除**も同じ仕組みです。

### コピー＆ペースト

| 対象              | できること                                                                                                                                                                                                                                                                            |
| ----------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| レイヤー          | コントローラー跨ぎ。参照パラメーターの自動追加、フレームの引き継ぎ                                                                                                                                                                                                                    |
| ステート          | Ctrl+C → レイヤーを切り替えて Ctrl+V。Behaviour・範囲内の遷移に加え、Entry / Exit / AnyState との接続も貼り付け先で張り直し。別コントローラーへ貼ると参照パラメーターを自動追加、ブレンドツリーは複製。同名がある場合のみ連番。サブステートマシンは対象外（レイヤーごとコピーを使用） |
| 遷移              | 条件つきでコピー＆ペースト                                                                                                                                                                                                                                                            |
| フレーム / ノート | Ctrl+C / Ctrl+V。クリップボードがレイヤー参照を持たないので別レイヤー・別コントローラーへ貼れます。ステートと一緒に選ぶと相対位置を保ったまま移動                                                                                                                                     |
| Behaviour         | インスペクターでタイトルをクリックして複数選択し、Ctrl+C / Ctrl+V で選んだものだけを他ステートへ                                                                                                                                                                                      |

レイヤー設定の「ステートを貼り付け」からは、表示を切り替えずに他レイヤーへ直接貼り付けられます。

### テンプレート

レイヤー / ブレンドツリーをテンプレート化して、**パラメーターリマップ付き**でインポート。

### クリップとリパス

- **クリップ一覧** — 参照している AnimationClip を使用ステートつきに一覧表示（名前で絞り込み・ステートへジャンプ・一括差し替え）
- **リパス** — 階層変更で壊れたバインディングをスキャンして From → To を一括書き換え。
  ウィンドウを開いている間だけ Hierarchy の変更に追従する**自動リパス**付き
- **Empty クリップ** — コントローラーごとにプレースホルダーを指定すると新規ステートに自動設定され、
  解析の「穴埋め」修正がモーション未設定のステートや空のブレンドツリースロットを一括補完します

### クリーンアップ

`.controller` に残った未参照のサブアセット（ゴミ）を検出してワンクリック削除。
逆に、使用中なのに Project ウィンドウに露出しているサブアセット（Behaviour の非表示フラグが
失われたもの）は、削除せず非表示に戻せます。

## 解析

### 静的解析 — DD StaticAnalyze

ツールバーの「解析」または `YozoLab > DD StaticAnalyze`。結果は独立ウィンドウに出るので、
グラフを編集しながら確認できます。多くの問題は**ワンクリックで修正**できます。

検出カテゴリ（20 種）:

| カテゴリ                   | 見ているもの                                                                    |
| -------------------------- | ------------------------------------------------------------------------------- |
| Unused Parameter           | どこからも参照されていないパラメーター                                          |
| Invalid Condition          | 型と合わない・壊れた条件                                                        |
| Duplicate Condition        | 同じ遷移内で重複している条件                                                    |
| Dead Transition            | 条件同士が矛盾していて成立しえない遷移                                          |
| Exit Time 0                | Exit Time が 0 の遷移                                                           |
| Soloed Transition          | Solo の消し忘れ                                                                 |
| Any State Retrigger        | Can Transition To Self の付けっぱなし（遷移先が頭から再生し直される定番の罠）   |
| Unreachable State          | 到達できないステート                                                            |
| Dead Entry Branch          | 通らない Entry 分岐                                                             |
| Terminal States            | 入ったら出られないステート群                                                    |
| Duplicate Name             | 同名のステート / レイヤー                                                       |
| Missing Motion             | モーション未設定                                                                |
| Missing Behaviour          | 参照の壊れた Behaviour                                                          |
| Empty Layer                | 中身のないレイヤー                                                              |
| Layer Weight               | レイヤーウェイトの設定ミス                                                      |
| WriteDefaults              | WD の混在                                                                       |
| Direct Blend Tree          | DBT の健全性（WD OFF のステート、ウェイトパラメーター未設定 / 欠落 / 非 Float） |
| Clip Bindings              | クリップのバインディング（壊れたパス等）                                        |
| VRC Parameters             | パラメーターストアとの不一致、組み込みパラメーターの型違い                      |
| AAP / Driver, AAP / Layers | AAP（アニメーションで書くパラメーター）とドライバ / レイヤーの噛み合わせ        |

### 動的解析 — DD DynamicAnalyze

`YozoLab > DD DynamicAnalyze`。コントローラーを**読む**のではなく**走らせて**答える解析です。
隠しオブジェクト上の本物の Animator を手でステップし、結果を**波形**として見ます
（Unity Profiler ＋ gtkwave のような窓。Play / Pause / コマ送り / スクラブ、行の絞り込み、
ポインタ位置でのズーム）。

時間はユーザーが決めます — FPS・秒数・**ジッタ**（各フレーム長のばらつき）・シード。
シードが同じなら完全に同じ実行になります。

<details>
<summary><b>装着者とリモートのモデル</b>（何が相手に渡り、何が渡らないか）</summary>

Parameter Driver は SDK に走らせるのではなく**自前で適用**するので、SDK の有無に依存せず、
装着者とリモートを区別でき（`localOnly` / `IsLocal`）、間に割り込めます。

**装着者のコピーと他人のコピー**を同じ時計で走らせ、両者の間を渡るのは
**同期パラメーターと VRChat 組み込みパラメーターだけ**です。

- 組み込み（Gesture / Viseme / Grounded / Upright / スケール系…）は**アバターの同期枠とは無関係に
  プラットフォーム側が常時同期**するので、同期パラメーターに入れなくても相手側に届きます。
  周期サンプルには乗らないので**その周期ぶん遅れず**、-1〜1 の 8bit 丸めも受けません
  （VelocityZ が 1 に張り付くのは実機に無い挙動です）
- 逆に `IsLocal` と `IsOnFriendsList` は**見る側ごとの値**、`AvatarVersion` などはローカル専用なので渡りません

**リモートは複数人にできます** — 人ごとに入室時刻とサンプル損失を別々に持ち（送信は 1 回、
配送だけが人ごと）、行は `Remote` / `Remote 2` … と分かれます。「A が居るところに B が
周回の途中で入ってくる」は、リモートが 1 人だけの実行では最初のフレームでしか試せない状況です。

**相手の入室時刻を指定できます**。0 は全員同時読み込みですが、それはインスタンスの最初の 1 分を
過ぎると起きなくなる唯一の状況です。あとから来た相手は**同期値を一括で受け取り**、残りは自力で
追いつきます（＝到達した index をそのまま解釈する側になる。追いつけたかを示すフラグ群は
まさにこのためのもの）。

同期は**周期サンプリング**として模擬します。1 周期の中で起きて消えた変化は届かず、1 周期に
2 回の変化は 2 回目だけが届きます（＝デコーダが index の変化を取りこぼす理由そのもの）。
値は実際の精度で丸められ（Float は -1〜1 を 8bit、Int は 1 バイト、Bool は 1 ビット）、
損失はサンプル単位です（＝ index とチャンネルが食い違うことはない）。

</details>

<details>
<summary><b>近似の明示</b>（黙って食い違うより、前提として言わせる）</summary>

そのコントローラーに即して、近似している箇所を名指しで表示します。

- 条件付き Entry 遷移を持つレイヤーは既定ステートから始まる
- 自分自身から入り直せるドライバは 1 回しか走らない
- レイヤーをまたぐドライバの伝播が 1 フレーム遅れる
- 実行されないビヘイビア（重みを動かす Layer Control だけは記録値に影響する）
- ロコモーション系（Velocity・AngularY）は両方のコピーで同じ値になるが、実機では相手側の
  コピーだけがプレイスペース移動を数える

SDK が入っていれば、DD が名前で読み書きしている想定（`ChangeType` の番号・フィールド名・
発火が `OnStateEnter` であること）を**実際の SDK 型と突き合わせるテスト**が走ります。

</details>

<details>
<summary><b>ライブ / バッチ / 記録の保存</b></summary>

**ライブ**に切り替えると同じクライアントを開いたまま EditorUpdate で回し続け、
**波形の値セルをそのまま書き換えて**その場で結果を見られます（行が誰の値かを示しているので、
操作用の別パネルは持ちません）。Trigger だけはチェックボックスではなく**押しボタン**で、
波形には**1 フレームのパルス**として出ます（遷移に消費された瞬間に Mecanim が下ろすので、
残った値だけを記録したら押した跡がどこにも残りません）。履歴は指定秒数ぶんの窓。
行はスコープごとに折りたため、既定では**一度も動かなかった信号を隠します**
（見出しに隠した数が出るので「無い」と「静かなだけ」を区別できます）。

**バッチ**側は時刻指定の入力（Stimulus）をウィンドウ上で編集でき、シードを固定すれば
完全に同じ実行を再現できます。

**リモート遅延の行**は、パラメーターごとに「相手が別の値を見ている時間」を出します —
多重化されたターゲットではそれが相手のコピーの古さ、つまり**リモート視点そのもの**です。

実行の記録は **AnimationClip（.anim）として保存・再読み込み**できます。記録は「時間 × 値の曲線」
そのものなので、Unity のアニメーションウィンドウでそのまま開けて差分も取れます
（信号のスコープ・型・ステート名はサブアセットとして同じファイルに同梱）。
**逆向きにも読めます** — 保存した実行を「時刻指定の入力」として読み込めば、ある実行が記録した
値が次の実行の入力になります（別の同期周期・別のフレームレート・別のシードで試す）。
保存した実行は**ゴーストとして重ねて比較**もできます（クリップ > 重ねて比較…）。合わせるのは
フレーム番号ではなく**時刻**なので、ジッタで両者のフレーム長が違っていても同じ瞬間が同じ列に来ます。
**Shift+クリックで第 2 カーソル**を置くと、カーソルとの**Δ（経過秒）**がツールバーに出ます —
「トグルを押してからレイヤーが動くまで」のような、実行に投げかける問いのほとんどは長さの問いです。

独立したフォルダと名前空間にあり、コアへの依存は一方向・3 型のみ（asmdef を置くだけで切り出せます）。

</details>

## 生成ツール

### オブジェクトガジェット

**リンクしたプレハブの中のオブジェクト**を対象にする仕掛けです（[プレハブ連携](#プレハブ連携)が前提）。
現在の種類はトグル 1 種: 対象オブジェクト群をパラメーターで ON/OFF するクリップと配線を自動生成します。
ホーム画面の Object Gadgets カード「+ Add Gadget」から。

- 方式は 2 つ: **新規レイヤー**（Bool + OFF/ON 2 ステート + 即時遷移）と
  **Direct ブレンドツリー**（Float で駆動する 1D ツリーを 1 レイヤーに集約）
- パラメーターの新規作成 / 既存流用、初期状態 ON、対象ごとの反転のほか、コンポーネントの
  enabled・ブレンドシェイプ・任意プロパティも同じトグルに束ねられます
- 対象は**参照で保存**し、パスは表示のたびに導出 — プレハブ側のリネームや親替えに追従します
- クリップは生成させる代わりに**手持ちの .anim を書き込み先に指定**できます。DaerD が書くのは
  そのガジェット自身の行だけで、他のカーブには触れず、ファイルも消しません
- ガジェットの削除はコントローラー側の生成物だけを消し、**プレハブには触れません**

### DBT ガジェット

Float の毎フレーム演算を行う Direct ブレンドツリーの仕掛け（WD ON の 1 ステート + ネストしたツリー）を自動生成。
ホーム画面の DBT Gadgets カード「+ Add Gadget」から。生成物はコントローラーのサブアセットとして保存され、
Direct ブレンドツリーのみのレイヤーはレイヤー一覧に「DBT」バッジが付きます。

**所要フレーム数は値によらず一定**で、連鎖すると加算されます:

| フレーム  | ガジェット                                                                                                                                                             |
| --------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 1         | 加算・減算（Ranged 版も同じ）・乗算・AND / OR / NOT・Float As Bool・リマップ・sin / cos / tan・LUT (Curve)・atan2・平方根・逆平方根・log2・exp2・指数スムーズ (Smooth) |
| 2         | 逆数・符号付き乗算・線形スムーズ (Smooth (Linear))                                                                                                                     |
| 3         | 逆数 (Ranged)・除算                                                                                                                                                    |
| 4         | 除算 (Ranged)・符号付き除算・累乗                                                                                                                                      |
| 5         | 桁分解                                                                                                                                                                 |
| N（1〜8） | Buffer (Delay)                                                                                                                                                         |

スムーズ 2 種だけは「段」ではなくフィルタなので、この数字は**最初の応答までの時間**です
（落ち着くまでの時間はスムーズ量の問題で、グラフの形とは関係ありません）。

<details>
<summary><b>精度・符号・時系列ズレの扱い</b></summary>

- **除数の範囲を宣言できるなら Reciprocal (Ranged) / Divide (Ranged) が最善**です。除数を 1 以上へ
  持ち上げて厳密側だけで割るので、**逆数の 240 上限もルックアップ表の誤差もありません**
- **符号付き乗算 / 除算** — Direct の重みは負をゼロに切り捨てるため素の乗除算は正数専用です。
  符号付き版は入力を正負の半分に分けて 4 象限を合算するので、どの符号の組み合わせでも正しく計算します
  （レンジが縛るのは入力だけで、積は範囲外へ出られます）
- **平方根・逆平方根・log2・exp2** は窓（入力レンジ）を宣言するだけの 1 フレームのテーブル。
  サンプルは関数に合わせて配置します（平方根と対数は等比、指数は等間隔 — どちらもその方が誤差が全域で一定になる）
- **累乗**は底も指数もパラメーターにできる唯一の形で、log2 → 符号付き乗算 → exp2 の 4 フレーム
  （中間レンジは宣言した 2 つから自動で決まります）
- **LUT (Curve)** は任意のカーブを 1D ブレンドツリーの区分線形テーブルにベイク。
  **atan2** は方向ベクトルから角度を「周」単位（0..1）で返す 2D FreeformDirectional の方向 LUT で、
  結果をそのまま sin / cos へ渡せます。どちらも補助レイヤーなしでツリー内に収まります
- **Buffer (Delay)** は入力をちょうど N フレーム遅らせるコピー。ブレンドツリーの計算は 1 段ごとに
  1 フレーム遅れるため、段数の違う分岐が同じパラメーターの別フレームの値を見てしまう
  「時系列ズレ」を、浅い側にバッファを挟んで補正します
- 逆数・除算・フレーム時間・三角関数はコントローラー末尾に専用の補助レイヤーを追加します

</details>

### 巡回同期（Async Sync / パラメーター圧縮）

指定したパラメーター群を「インデックス + 型別値チャンネル」という少数の同期パラメーターに**時分割多重**します。
VRChat の約 0.3 秒の同期周期を利用し、ローカル側の巡回ステートが Parameter Driver で値を順番に載せ、
リモート側が AnyState デコーダーで書き戻します。同期コストのプレビュー付き（ホーム画面から）。
DaerD が生成したレイヤーにはレイヤー一覧でアイコンが付き（ツールチップに由来が出ます）、
ウィザードから同じレイヤーを再生成、ホーム画面の行から**削除**できます
（レイヤー・生成パラメーター・同期リクエストを掃除。IsLocal・転送対象・Empty クリップは消しません）。

- インデックスは既定の「自動」でパラメーター数に応じて Int / Bool の安い方を選択（同ビット数なら同期パラメーター 1 個で済む Int）
- Float チャンネル数は 1〜8。1 ステップで複数の Float を運びスロット数を減らせます（チャンネル 1 本につき同期 8 bit）
- 「巡回順（Cycle Order）」エディタで順番をドラッグ指定。行ごとの実際の更新間隔（〜秒ごと）と
  巡回全体のタイムライン（F → B → I …）を表示。対象一覧には検索窓付き
- IsLocal や巡回同期自身が生成したパラメーターは対象に選べません
- 生成 State にはコントローラーの Empty クリップを自動割り当て（ステップ時間はクリップ長で正規化）
- 1 周の所要時間・優先パラメーターの更新間隔・追加コスト 0 で入るスロット数・圧縮しても減らない構成・
  パペット操作で駆動されている対象などを警告表示

<details>
<summary><b>リクエスト (Req) / 初期化フラグ (Ready) / ズレ疑い (Stale) / グループ</b></summary>

**同期リクエスト（Req）** — 有効にしたパラメーターは順番を待たずに送れます。ローカルの Bool フラグが
立つと巡回は 1 ステップぶん**寄り道**してそのスロットを送り、離れた場所へ巡回を戻します。位置を戻すので
巡回が止まらず、寄り道どうしは連続しないので、どれだけ叩かれても 1 周は最大 2 倍までです（ウィザードに秒で表示）。
「変わった瞬間に送りたい」はこちらの役目で、**×N 列は読み取り専用の表示**です — 重みは 1 周の配分を
書き換えるだけ（1 つを上げると 1 周が伸びて他が遅くなる）なので、ウィザードから新しい重みは配れません。
ただし C# レシピの `.Rate(...)` などで**保存済みの重みはそのまま読み込み・生成・エクスポート**され、
その場合だけ ×N 列に実際の枠数が出ます（間隔を空けきれない重みは実効値に丸めて警告）。明示スケジュールや
手書きのステップを持つ設定も同様に表示・生成され、「Back To Cycle Order」で通常の巡回順へ戻せます。

**リモート初期化フラグ（Ready）** — そのクライアントが全スロットを 1 度以上受信し終えた時点で 1 になる
ローカル Bool を生成します。リモートには装着者へ問い合わせる手段が無いので、これがその代わりです。
各スロットの受信ビットは一度立ったら落ちないため、周回の途中で入っても最大 1 周でラッチし、判定に
時間窓もマージンも要りません。装着者側は最初から 1（自分の値はどこにも行っていないため）なので、
「初期化を終えたリモート」は `Ready && !IsLocal` と書けます。同期ビットの増加は 0、費用はスロット数ぶんの
ローカル Bool と監視レイヤー 1 枚。

**同期ズレ疑いフラグ（Stale）** — 1 周のあいだに全スロットが届かなかったとき 1、届いた周で 0 になる
ローカル Bool。判定は「1 周に 1 回だけ送られるスロット」が回ってきた瞬間なので、タイマーもマージンも要らず、
リクエストで 1 周が伸びても誤検知しません。受信ビットを落とすのは監視レイヤー自身で、読む側と落とす側が
同じレイヤーに入るため競合しません（マーカーのステップはまだ 1 ドウェル丸ごと残っているので、次のスロットは
数百フレーム先）。1 周に 1 回だけ送られるスロットが無い巡回（全スロットが複数回送られる／全部リクエスト対象）
でも、マーカー用にインデックス値を 1 つ買い足して必ず作れます（費用はインデックス値 1 個とデコーダーステート
1 個。1 周の長さもペイロードもタイミングも変わりません）。作れないのは「全ステップが同じスロットを送る」巡回
＝スロットが 1 つしかない設定だけで、この場合は 1 周のうちに欠けうるものが何も無いため、黙って落とさず
エラーで拒否します。周の途中で入ったリモートはその周のあいだ 1 になるので、「初期化中」と区別したいときは
Ready と組み合わせます。

**グループ** — 同時に変わるべき値が、リモートで必ず同時に代入されます。デコーダは実パラメーターではなく
影パラメーター（`Hold/`）へ受け、**全メンバーが届いた時点で 1 個の Parameter Driver が一括コピー**するので、
同時性がタイミングではなく構造で保証されます（1 つのドライバのエントリは同じフレームで走るため）。
揃わなかった周はコミットせず、**ちぎれた新しい状態ではなく、揃った 1 周前の状態**のまま次の周で治ります。
同じステップに載るパラメーターは元々一緒に届くのでグループは不要で、その場合は警告を出します
（グループが要るのは型が違う・チャンネルが足りないなどで同じステップに入れられないとき）。同期ビットの増加は 0。

</details>

## プレハブ連携

コントローラーを、それを合流させる**ギミックプレハブ（MA Merge Animator）に紐づけ**ます。
リンクと設定は**すべてコントローラー側に保存**され、**プレハブには 1 バイトも置きません** —
DaerD の無い環境でそのプレハブを開いて保存しても、何も壊れず何も消えません。

- **Prefab Link カード**（ホーム画面）: プレハブを D&D するか「Scan & Link」でプロジェクトを走査。
  候補になるのは**このコントローラーを合流させる Merge Animator を持つプレハブだけ**で、
  DaerD が勝手に選ぶことはありません
- リンクの状態を常時表示: プレハブ喪失 / Merge Animator 喪失 / 別コントローラーを合流するよう
  変わった / MA 未インストール。**どの場合もリンクを勝手に修理・付け替えしません**（Rescan は明示操作）
- **パラメーターストアのスロットもこのカード**にあります。リンク時にストアが未設定なら、
  プレハブ自身の MA Parameters を同時に割り当てます
- プレハブへの書き込みは**明示ボタンだけ**（例: ルートへ MA Parameters コンポーネントを追加）。
  パッケージマネージャ管理下のプレハブと、プレハブモードで未保存のものは**拒否**します

オブジェクトガジェットの対象と、C# Recipe の `Objects()` の検証は、このリンクを起点に解決されます。

## C# Recipe

コントローラー全体または選択レイヤーを、**それを再構築する編集可能な C#** へエクスポートします。
API は [AnimatorAsCode](https://github.com/hai-vr/av3-animator-as-code) V1 準拠の方言
（`NewState` / `WithAnimation` / `TransitionsTo(x).When(go.IsTrue())` / `Drives` / `DrivingRemaps` …、
パラメーターは型付きハンドル）。生成コードは冒頭に API チートシート付きで、
**AI に渡してそのまま編集してもらえる**形式です。

- クリップ / マスク参照は Recipe アセット（ScriptableObject）のフィールドに自動代入され、
  インスペクターで D&D 差し替え可能 — **コードに GUID は一切入りません**
- 出力は **partial class を分けた 2 ファイル**。`<Name>.Generated.cs` は毎回作り直される機械側、
  `<Name>.cs` は**あなた（や AI）の Build() で、DaerD は二度と上書きしません**（実行されるのはこちら）。
  エクスポート → 整形 → 生成 → コントローラー編集 → 再エクスポート、というループで整形が消えないための分割で、
  再エクスポートの変更は Generated 側の git diff にきれいに出ます
- Recipe アセットの「エクスポート側と比較」は両者が宣言する内容（IR）を突き合わせ、整形が意味を変えて
  いないことを保証します — 読み方ではなく**出来上がる物**の比較なので、ループやヘルパーで書き直しても通ります
- 「生成」で対象コントローラーへ適用（部分 Recipe は同名レイヤーをその場で置換、exclusive は全体を所有）、
  「検証」でコードと実物の乖離をレポート。Recipe 所有レイヤーにはレイヤー一覧でアイコンが付きます
- **コントローラーは自分のレシピの所在を覚えています** — 再エクスポートは既存のレシピを更新するのが
  既定で、フォルダ移動や同名コントローラーで重複ペアができません。ホーム画面の C# Recipes カードに
  状態（最新 / コンパイル待ち / コンパイルエラー / 対象不一致）と生成・検証・開くのボタンが並びます
- **鮮度ガード** — コンパイル待ちやコンパイルエラーで「実行されるコードが .cs より古い」あいだは、
  生成・検証は黙って古いコードを走らせず、理由を表示して止まります

正しさはラウンドトリップで担保されています（エクスポータは実際にビルダー API を実行しながら
その呼び出し列を記録する方式なので、出力コードと検証済み動作が構造的に一致します）。

### ウィンドウを開かずに書き出す

解析や CI のために、スクリプト / batchmode からも同じエクスポートを呼べます。

```csharp
var source = RecipeExport.ToSource(controller);        // ファイルを作らずコードだけ返す
var diffs  = RecipeExport.Verify(controller, source);  // 空 = そのコードは元コントローラーを完全に再構築する
RecipeExport.ToDirectory(controller, "/tmp/recipes");  // プロジェクト外へ 2 ファイル
RecipeExport.ToProject(controller, "Assets/Recipes");  // asmdef と Recipe アセットまで（ウィンドウもこれを呼ぶ）
```

```bash
Unity -batchmode -quit -projectPath P \
  -executeMethod Yozolab.DaerD.Authoring.RecipeExportCli.Run \
  -daerdController Assets/FX.controller -daerdOut /tmp/recipes -daerdVerify
```

`-daerdOut` がプロジェクト内ならフル書き出し、外なら `.cs` 2 ファイルのみ。省略すると各コントローラーの隣へ。
他に `-daerdNamespace` / `-daerdClass` / `-daerdLayers a;b` / `-daerdNoAsset` / `-daerdNoAsmdef` / `-daerdMigrate`。

### 手書き / 高度な使い方

- `c.Raw(controller => …)` — DaerD / Unity の全 API へのエスケープハッチ
- `c.AsyncSync()` — 巡回同期をフル設定。ウィザードには無い**明示スケジュール**
  （`Schedule("Hue","Outfit","Hue","Tail")`）まで指定できます
- `c.Gadgets("DBT")` — DBT ガジェットを C# で並べて 1 レイヤーに生成（引数はパラメーターハンドルでも文字列でも可）
- `c.Objects()` — オブジェクトガジェットを宣言（`.Toggle("Hat").Shows("Head/Hat")` …）。対象は
  リンク先プレハブ内のパスで書き、生成時に**全対象を検証してから**組み立てます — 欠けがあれば
  何も作らずに全部を列挙するので、別プレハブへ移植したときの TODO リストになります。
  **プレハブには書きません**

<details>
<summary><b>ガジェットのフレーム追跡</b></summary>

ビルダーは各パラメーターが入力から何フレーム遅れているかを追跡していて、`FramesBehind("Out")` で
書いている最中に読めます（Buffer の段数を手で数えずに計算できる）。同じ信号が別の深さで 1 つのガジェットに
入ると、両方の年齢と挿すべき Buffer 呼び出しを名指しで報告します。無関係な 2 信号の年齢差は報告しません
（フレーム時間 × レートのような、そもそも揃える対象が無い組み合わせ）。`.RequireAligned()` を付けると
報告ではなく生成拒否に変わります。生成のたびにそのレイヤー・補助レイヤー・出力パラメーターの名前空間
（`Out` と `Out/…`）を掃除してから作り直すので、何度 Generate しても積み上がりません。

エクスポートしたコードのうち、ツリーがそのまま出て読みづらいガジェットレイヤーだけをガジェット呼び出しに
書き換える、という使い方ができます。

</details>

パラメーターストア（VRC Expression Parameters アセット **または Modular Avatar の MA Parameters

| キー                           | 動作                                                                                                                                                |
| ------------------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------- |
| I / O / P                      | 入ってくる遷移 / 出ていく遷移 / 繋がっている遷移すべてを選択                                                                                        |
| F / A                          | 選択をフレーム / グラフ全体をフレーム                                                                                                               |
| M / T                          | 配線。M = 選択を遷移元としてマーク、T = マーク済み → 選択へ接続。マークが無いときの T はクリック順に連結するので、**2 個選んで T だけで繋がります** |
| ↑ ↓ ← →                        | 隣のノードへ選択を移動                                                                                                                              |
| F2 / Ctrl+F2                   | 選択したステート・フレーム・ノートをリネーム / ステートのクリップをリネーム                                                                         |

| Ctrl+D                         | 選択ステートを複製                                                                                                                                  |
| Ctrl+A / Ctrl+Shift+A          | 全ノードを選択 / 全遷移を選択                                                                                                                       |
| Ctrl+F                         | 検索欄へ                                                                                                                                            |

インスペクター側では Ctrl+C / Ctrl+V / Ctrl+Shift+V が選択中の遷移・Behaviour に効きます。

**Preferences > Yozolab > daerD の「キーボードショートカット」で変更・個別に無効化**できます
（グラフとインスペクターは別枠なので、同じキーに別の役割を割り当てられます）。
